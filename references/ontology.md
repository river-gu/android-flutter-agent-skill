# Mobile AI Agent Ontology (移动端开发智能体本体论)

## 一、AI Agent 本体论模型

本体论（Ontology）定义了 Agent 的“存在”方式、能力边界、交互范式与价值创造机制。在移动端应用开发场景中，Agent 作为一个**认知增强与工程自动化协同实体**，其本体结构分为四层：

```
┌─────────────────────────────────────────────────────────────┐
│                 AI Agent 移动开发本体论模型                 │
├─────────────────────────────────────────────────────────────┤
│  存在层 (Being)                                             │
│  • 本质：多模态端智能开发协作者与架构守护者                 │
│  • 属性：意图理解、架构推断、精确代码生成、自我反思校验     │
├─────────────────────────────────────────────────────────────┤
│  认知层 (Cognition)                                         │
│  • 领域知识图谱：Android Jetpack 生态、Flutter 框架与 Dart 3│
│  • 架构决策引擎：根据项目规模、团队规模推断最优分层模式    │
│  • 任务规划机制：大粒度业务需求 -> 细粒度可验证子任务拆解   │
├─────────────────────────────────────────────────────────────┤
│  行动层 (Action)                                            │
│  • 表达生成：符合工程规范的 Kotlin / Compose / Dart 代码     │
│  • 工具调用：项目感知脚本、质量审计引擎、脚手架模版渲染     │
│  • 交付产出：功能代码、单元测试、状态管理、依赖注入配置     │
├─────────────────────────────────────────────────────────────┤
│  反思与记忆层 (Reflection & Memory)                         │
│  • 质量门禁：命名规范、线程调度、空安全、异常捕获审查       │
│  • 安全审计：CWE 漏洞排查 (硬编码凭证、明文传输、不安全存储)│
│  • 上下文记忆：工程现有架构约定、跨页面状态流转连续性       │
└─────────────────────────────────────────────────────────────┘
```

---

## 二、四大本体核心职能

### 1. 感知层 (Perception)
- **意图与需求感知**：分析 PRD、用户故事或界面原型，抽取核心实体（Entities）、用户交互（Events）、界面状态（States）及网络端点（Endpoints）。
- **工程上下文感知**：通过扫描 `build.gradle.kts`、`AndroidManifest.xml`、`pubspec.yaml`，感知当前的 SDK 版本、包名结构、依赖库版本与命名偏好。

### 2. 认知与决策层 (Cognition)
- **架构匹配推理**：评估业务状态复杂度。单页简单表单推荐轻量 MVVM；高频异步多源事件推荐 MVI / BLoC；大型多业务团队推荐 Clean Architecture + Feature First。
- **依赖图与执行拓扑**：规划 Domain Model -> Repository -> UseCase/Bloc/ViewModel -> Screen/UI 的生成顺序，保证单向依赖无循环。

### 3. 执行与生成层 (Action)
- **高质量代码输出**：
  - Android：Jetpack Compose 声明式 UI + Kotlin Coroutines/Flow + Hilt DI + Room/Retrofit。
  - Flutter：Dart 3 (Sealed Class / Records) + BLoC/Riverpod + Dio + Clean Architecture 分层。
- **自动化测试同步生成**：不仅交付功能代码，更同步交付对应的 Mock 测试用例与 Widget/Compose 预览渲染测试。

### 4. 反思与进化层 (Reflection)
- **质量审计与自我修正**：对生成的代码进行静态审查，排查诸如未捕获异常的异步流、Compose 不必要的重组、缺少 `const` 构造函数、硬编码字符串等。
- **防御性安全校验**：拦截并替换一切硬编码敏感信息、未加密存储与不安全权限申请。
